DNumerical recipes (one-glance)

Huffman in 5 moves

  1. Count frequencies (table).
  2. Repeatedly merge the two smallest (write the list after each merge).
  3. Draw the tree: left = 0, right = 1.
  4. Read codes root → leaf; bits = Σ f × code length.
  5. Compare with 8 × N (or fixed-length); saved = difference.

Lempel-Ziv in 4 moves

  1. From the remaining text take the longest known prefix + one new symbol.
  2. Store it as the next dictionary entry.
  3. Output (index of known part)(new symbol); no match → just the symbol.
  4. Bits = tokens × (index bits + symbol bits).

RMS in 4 moves

  1. Priority: smaller period = higher.
  2. U = Σ C/T; U ≤ 1 (necessary); U ≤ n(2^{1/n} − 1) (sufficient).
  3. If UB fails, use RTA: R = C + Σ ⌈R/Tⱼ⌉Cⱼ until stable; check R ≤ D.
  4. Gantt over the hyperperiod (LCM of periods).

EDF in 3 moves

  1. D = T: schedulable ⇔ U ≤ 1. D < T: Σ C/D ≤ 1 is sufficient.
  2. At every tick, run the ready job with the earliest absolute deadline (tie: keep the running job).
  3. Draw the Gantt up to the hyperperiod and mark any miss.

Compression basics: why, entropy, lossless vs lossy

What compression is, how to measure how much a message can be compressed (entropy), and the two families of methods.

PYQ: A-Q1b (3 M)Entropy numericals

Your path through this unit

Read each lesson, answer its "Check yourself", then tick it.

    1Learn it, step by step

    Lesson 1

    What data compression is, and why we need it

    In plain words

    Compression means storing or sending the same information using fewer bits. When you text "brb" instead of "be right back", you have compressed the message. Your friend can still recover the meaning.

    Embedded devices have small memory, slow links and batteries. Fewer bits means less storage, faster transmission, and a free I/O bus.

    Write this in the exam
    • Why compress: make optimal use of limited storage space; save time and optimize resources.
    • If compression/decompression is done in the I/O processor, less time is needed to move data to/from storage, which frees the I/O bus for other work.
    • When sending over a communication line: less time to transmit and less storage at the host.
    • Data compression is about storing and sending a smaller number of bits.

    Remember: same information, fewer bits: less storage, less transmit time, a freer bus.

    Check yourself: give two benefits of compressing data before sending it over a network.

    Less transmission time (lower bandwidth) and less storage needed at the receiving host.

    Lesson 2

    Two families: lossless and lossy

    In plain words

    Lossless: after decompressing you get back exactly the original, bit for bit, like a ZIP file. Essential for text, programs, bank records and medical reports, where one wrong bit is a disaster.

    Lossy: some detail is thrown away for good, but humans don't notice, like a JPEG photo or an MP3 song. It achieves much higher compression and is used for images, video and audio.

    Remember: lossless = exact (text, code, records) · lossy = "looks the same" (photo, video, song).

    Check yourself: which family would you use for a hospital's patient lab reports?

    Lossless. Medical data cannot afford to lose any information.

    Lesson 3

    Entropy: how much information a message really has

    In plain words

    If a message is "AAAAAAAAAA", you learn almost nothing new from each letter; it is predictable. If every letter is different and random, each one carries a lot of information. Entropy measures this: the average number of bits per symbol truly needed. No lossless method can go below the entropy, so it is the best possible target.

    H = − Σ p(x) · log₂ p(x)   (bits per symbol)
    Recipe: entropy numerical
    1. Count each symbol's frequency f; total N.
    2. p = f / N for each symbol.
    3. For each symbol compute −p·log₂p. Tip: log₂x = ln x / ln 2 = log₁₀x / 0.301.
    4. Add them: H. Total minimum bits ≈ N × H.

    Worked example (Paper C message EFFFBBBGGGDBGFFFDDBEEGGBFFF, N = 27):

    Symbolfp−p log₂ p
    F90.3330.528
    B60.2220.482
    G60.2220.482
    E30.1110.352
    D30.1110.352
    H2.197 bits/symbol

    So the message needs at least 27 × 2.197 ≈ 59.3 bits. Huffman achieves 60 bits (Unit 3), almost perfect.

    Write this in the exam

    Entropy is the measure of information content in a message. Messages with higher entropy carry more information than those with lower entropy. Find p(x) of each symbol; H(x) = −p(x)·log₂p(x). The average entropy over the whole message is the sum over all n symbols.

    Remember: entropy is the floor: Huffman's average length L ≥ H, and efficiency = H / L.

    Check yourself: what is the entropy of a message where all 4 symbols are equally likely?

    Each p = 1/4, so H = 4 × (−¼ log₂ ¼) = 4 × ¼ × 2 = 2 bits/symbol. With no redundancy, compression can't beat 2 bits.

    Lesson 5

    Why encrypted or random data doesn't compress (Paper A-Q1b)

    In plain words

    Every lossless method works by finding patterns: repeated symbols (RLE), some symbols more common than others (Huffman), repeated phrases (LZ). Good encryption deliberately destroys all patterns: the output looks like random noise, every byte value is about equally likely, and nothing repeats. Its entropy is at the maximum (≈ 8 bits per byte), so there is nothing left to squeeze.

    Write this in the exam (3 marks)
    • Reason: encryption produces high-entropy, uniformly distributed, pattern-free (pseudo-random) data. Lossless compression depends on redundancy, and there is none, so the file barely shrinks (it may even grow slightly because of headers).
    • Corrective measure: compress first, then encrypt. Compress the plain transaction records (which contain repeated fields, names, dates and amounts), then encrypt the smaller file.
    • Bonus: compressing first also means less data to encrypt and transmit. Use a lossless method (Huffman / LZ / DEFLATE) because financial records must be recovered exactly.

    Remember: compress → encrypt, never encrypt → compress.

    Check yourself: why does zipping a JPEG photo also save very little?

    A JPEG is already compressed, so its redundancy has been removed and the data is close to maximum entropy.

    MODULE 3 · UNIT 2

    Run-length encoding (RLE)

    The simplest compression: write a repeated symbol once, followed by how many times it repeats.

    PYQ: C-Q1(ii) (3 M)Numerical

    Your path through this unit

      1Learn it, step by step

      Lesson 1

      How RLE works

      In plain words

      Instead of saying "B B B B B B B B B", say "B, nine times". A run is a group of the same symbol in a row. RLE replaces each run with the symbol + its count.

      Write this in the exam

      RLE is the simplest compression method. It replaces consecutive repeating occurrences of a symbol with one occurrence of the symbol followed by the number of occurrences. Slide example: BBBBBBBBBAAAAAAAAAAAAAAAANMMMMMMMMMM → B09A16N01M10.

      Remember: each run is written as symbol + count.

      Check yourself: RLE-encode WWWWBBBWW.

      W4B3W2 (or W04B03W02 in the slide's 2-digit style).

      Lesson 2

      RLE on bit patterns

      In plain words

      RLE works even better on binary data where one symbol (say 0) is far more common. Since only two symbols exist, just write how many 0s come before each 1, as a fixed-size binary number.

      Original : 00000000000000 1 0000 1 1 000000000000
           └─ 14 zeros ─┘   └4┘   0   └─ 12 zeros ─┘
Counts   :      14           4    0        12
4-bit    :     1110         0100 0000     1100      → 1110 0100 0000 1100 (16 bits)
      Write this in the exam

      The method is more efficient if the data uses only 2 symbols (0s and 1s) in bit patterns and one symbol is more frequent than the other. Encode the number of 0s between successive 1s using a fixed number of bits.

      Remember: in binary RLE you only store the count of zeros before each 1.

      Check yourself: encode 0000000100000001 with 4-bit counts.

      7 zeros then 1, 7 zeros then 1 → 0111 0111.

      Lesson 3

      Calculating RLE size, and when RLE makes things worse

      Recipe: RLE numerical
      1. Split into runs; count the runs r and note the longest run.
      2. Symbol field = ⌈log₂ k⌉ bits (k distinct symbols). Count field = ⌈log₂(longest run + 1)⌉ bits.
      3. RLE size = r × (symbol bits + count bits).
      4. Compare with the original N × symbol bits (or N × 8).
      When RLE fails

      If runs are short (1–3 long), every run costs a symbol plus a count, so the "compressed" data can be bigger than the original. Example: ABCD → A1B1C1D1 doubles in size. RLE is great for images with large flat areas, fax pages and sensor logs that stay constant. It is poor for normal text.

      Remember: long runs → RLE wins · short runs → RLE loses (it can expand the data).

      Check yourself: 20 symbols, 4 distinct, 12 runs, longest run 3. RLE size vs original (fixed-length)?

      Symbol 2 bits, count ⌈log₂4⌉ = 2 bits → 12 × 4 = 48 bits vs 20 × 2 = 40 bits. RLE is worse.

      Final step

      Practice

      Do the RLE part of Scenario 3.3 (Unit 3) on paper, then check it. Try your own strings in the RLE lab.

      2Tips & traps

      Tip: Show the runs visually (underline each run) before writing the output. Examiners give marks for the method.
      Trap: Don't merge runs of the same symbol that are separated: BBB G BB is three runs.

      Huffman coding

      Frequent symbols get short codes, rare symbols get long codes. The most asked compression numerical in your papers.

      PYQ: A-Q1a (7 M)PYQ: B-Q1 (10 M)PYQ: C-Q1 (10 M)

      Your path through this unit

        1Learn it, step by step

        Lesson 1

        The idea: short codes for frequent symbols

        In plain words

        In Morse code, "E" (the most common English letter) is a single dot, while rare letters like "Q" are long. Huffman does the same with bits. Normally each character takes 8 bits. Huffman gives the most frequent character maybe 1–2 bits and a rare one maybe 4–5, so the total drops a lot.

        Huffman codes are prefix-free: no code is the beginning of another code. That is why a bit stream can be decoded without separators.

        Write this in the exam
        • Assign fewer bits to symbols that occur more frequently and more bits to symbols that appear less often.
        • There is no unique Huffman code, but every Huffman code for the same frequencies has the same average code length.

        Remember: common → short code, rare → long code, and no code is a prefix of another.

        Check yourself: is {A = 0, B = 01, C = 11} a valid Huffman-style (prefix-free) code?

        No. "0" (A) is a prefix of "01" (B), so "01" could be read as A then something else.

        Lesson 2

        The algorithm (slides) and how to break ties

        Algorithm from the slides
        1. Make a leaf node for each symbol, holding its frequency (probability).
        2. Take the two nodes with the smallest frequencies and connect them to a new node. Label the two branches 0 and 1. The new node's frequency = sum of the two.
        3. If only one node is left, the tree is complete. Otherwise go back to step 2.
        Tie rule used in this kit (write it in your answer)

        Sort ascending. When two nodes have the same weight, take the one that was in the list first (original symbols before newly merged nodes). The first node taken goes left (0), the second right (1). Different tie choices give different but equally good codes with the same total bits. Just state your rule and stay consistent.

        Remember: smallest two → merge → sum → repeat · left 0, right 1.

        Check yourself: frequencies 4, 6, 7, 3. Which two merge first, and what is the new node?

        3 and 4 merge into 7.

        Lesson 3

        Worked example from the slides

        Slide Table 15.1: A 17, B 12, C 12, D 27, E 32. The slide gets A 00, B 010, C 011, D 10, E 11, and so does our rule:

        The slide's encoding of "EAEBAECDEA" is 1100110100011011101100, the same as above.

        Remember: always write Steps 1–5 (count, merge table, tree, codes, compare).

        Check yourself: why is D (27) given a 2-bit code but B (12) a 3-bit code?

        B is less frequent, so it was merged early and sits deeper in the tree (longer path from the root). D was merged late, near the root.

        Lesson 4

        Encoding and decoding

        In plain words

        Encoding: replace each character by its code and join them. Write the per-character codes above the bit string, so the examiner can follow.

        Decoding: read bits from the left, one at a time. The moment the bits you have collected equal a code in the table, write that character and start collecting again. Because the code is prefix-free, there is never a doubt. With a tree: start at the root, go left on 0 and right on 1, and when you hit a leaf, output it and jump back to the root.

        Codes: A=00 B=010 C=011 D=10 E=11
Decode 11 00 11 010 00 11 011 10 11 00
       E  A  E  B   A  E  C   D  E  A   → EAEBAECDEA

        Remember: collect bits until they match a code, output the character, reset.

        Check yourself: with the codes above, decode 1001011.

        10 = D, 010 = B, 11 = E → DBE.

        Comparing Huffman with other methods

        Compute the size in bits of each under the same assumptions (same symbol-bit width), compare the numbers, and give the reason in one line (e.g. "runs are at most 3 long, so RLE's count overhead cancels its gain; Huffman exploits the frequency skew").

        Remember: compare in bits, then give the reason.

        Check yourself: which method suits "AAAAAAAAAAAABBBBBBBBBBBB"?

        RLE: 2 runs, A12B12. Huffman would still need 1 bit per symbol = 24 bits.

        MODULE 3 · UNIT 4

        Lempel-Ziv: dictionary-based compression

        Build a dictionary of phrases as you go and replace repeats with their index. This is the method behind ZIP, GIF and PNG.

        PYQ: D-Q1 (10 M)Slide exercise: LZ78

        Your path through this unit

          1Learn it, step by step

          Lesson 1

          The dictionary idea

          In plain words

          Imagine you and a friend both keep a numbered list of phrases. The first time you say "good morning", you both write it down as #5. Next time you just say "#5". Lempel-Ziv does this with strings: both sender and receiver build the same dictionary while communicating, so the dictionary itself never has to be sent.

          Write this in the exam
          • Lempel-Ziv is dictionary-based encoding.
          • Create a dictionary (table) of strings used during communication.
          • If both sender and receiver have a copy, previously encountered strings can be substituted by their index.
          • Two phases: building an indexed dictionary and compressing a string of symbols.

          Remember: a phrase seen before is sent as its index.

          Check yourself: does the dictionary have to be transmitted with the data?

          No. The decoder rebuilds exactly the same dictionary from the tokens as it decodes.

          Lesson 2

          The compression algorithm, on the slide example

          Algorithm (slides)
          1. Extract the smallest substring that cannot be found in the dictionary from the remaining text (= longest known part + one more symbol).
          2. Store that substring in the dictionary as a new entry with the next index.
          3. The known part is replaced by its index.
          4. Insert the index and the last character of the substring into the compressed string.

          Slide example: BAABABBBAABBBBAA → B, A, 2B, 3B, 1A, 4B, 5A

          Remember: longest known part + one new symbol = new entry; output = index + symbol.

          Check yourself: at step 3 the remaining text is "ABABBBAABBBBAA". Why is the parsed string "AB" and not "A"?

          "A" is already entry 2, so it is known. Add the next symbol: "AB" is not in the dictionary, so it becomes entry 3 and the output is 2B.

          Lesson 3

          Output format and counting bits

          In plain words

          Every token is really a pair (index, symbol). The slides write 2B for (2, B) and just B for (0, B), where 0 means "no known part". To store the output in binary you need bits for the index and bits for the symbol.

          bits = number of tokens × ( ⌈log₂(entries + 1)⌉ + ⌈log₂(symbols in alphabet)⌉ )

          The "+1" leaves room for index 0 (no match). With 9 entries you need ⌈log₂10⌉ = 4 index bits. A 4-symbol alphabet needs 2 symbol bits.

          Tip: Short strings often expand under LZ, because the dictionary only pays off on long text with many repeats. If your answer is bigger than the original, say so. That is a correct and thoughtful observation.

          Remember: each token = index bits + symbol bits.

          Check yourself: 7 tokens, 7 entries, alphabet {A, B}. How many bits?

          Index ⌈log₂8⌉ = 3, symbol 1 → 7 × 4 = 28 bits.

          Lesson 4

          Decompression: the inverse process

          In plain words

          Read the tokens in order. For each token, look up the index in the dictionary built so far (0 = nothing), add the symbol, output the result, and store it as the next entry. This is exactly the compression process run backwards.

          Remember: dictionary[index] + symbol → output it and store it.

          Check yourself: decode A, B, 1B, 3A.

          1 = A, 2 = B, 3 = A+B = AB, 4 = AB+A = ABA → A B AB ABA → ABABABA.

          Final step

          Practice

          Solve Scenarios 3.4 and 3.5 on paper, then check. Try any string in the LZ lab.

          Longest Known + One New = "LK-ON"

          MODULE 3 · UNIT 5

          Lossy compression: JPEG, MPEG and audio

          How photos, videos and music are shrunk by throwing away what our senses can't notice.

          Theory + diagramsScenario questions

          Your path through this unit

            1Learn it, step by step

            Lesson 1

            Why lossy is acceptable for media

            In plain words

            Our eyes can't see tiny colour changes between neighbouring pixels, and our ears can't hear quiet sounds hidden under loud ones. Lossy methods delete exactly that invisible or inaudible detail. The file becomes 10–20× smaller and still looks and sounds the same to us.

            Write this in the exam

            Lossy methods are used for compressing images and video files, because our eyes cannot distinguish subtle changes, so lossy data is acceptable. These methods are cheaper and take less time and space. Methods: JPEG (pictures and graphics), MPEG (video), MP3 (audio).

            Remember: lossy removes detail you can't see or hear.

            Check yourself: why is lossy compression unacceptable for firmware images?

            A changed bit in machine code breaks the program, so firmware needs exact (lossless) recovery.

            JPEG: blocks → DCT → quantization → zig-zag + RLE

            In plain words
            1. Blocks: the grayscale picture is cut into 8×8 pixel blocks, so each calculation stays small.
            2. DCT (Discrete Cosine Transform; the slide calls it "Discrete Concise Transform"): turns the 64 pixel values into 64 numbers describing how much the block changes. The top-left value is the average brightness; the rest describe finer and finer changes. For a smooth gradient, almost all values become 0. Relationships are kept, and redundancy is revealed.
            3. Quantization: divide each value by a constant and drop the fraction. Small values become 0. This is the lossy step.
            4. Compression: read the table in a zig-zag path so the 0s (bottom-right) cluster together at the end, then compress with lossless run-length encoding.

            DCT example (slide 102)

            A gradient block with every row "20 30 40 50 60 70 80 90" becomes T(m,n) = 400, −146, 0, −31, 0, −1, 0, −8 in the first row and 0 everywhere else. Only 8 numbers are non-zero out of 64, which is the redundancy DCT reveals.

            Remember: Big Dogs Quietly Zig-zag = Blocks, DCT, Quantize, Zig-zag + RLE.

            Check yourself: which JPEG phase actually loses information?

            Quantization. Dividing and dropping fractions can't be undone. DCT and RLE are reversible.

            MPEG: compressing video

            In plain words

            A video is a rapid sequence of pictures (frames). Two tricks: compress each frame like a JPEG (spatial), and avoid repeating what doesn't change between frames (temporal). In a news video only the reader's lips move, so why store the whole background 30 times a second?

            FrameMeaning

            P (predicted)Stores only the changes from the previous I or P frame.

            Write this in the exam

            Remember: spatial = inside one frame · temporal = between frames · I is full, P is forward, B is both ways.

            Audio compression: predictive and perceptual

            In plain words

            Predictive encoding: neighbouring audio samples are close in value, so send only the difference from the previous sample (small numbers need fewer bits). Used for speech.

            Write this in the exam

            Remember: speech → predictive (differences) · music → perceptual (MP3).

                        Rate Monotonic Scheduling (RMS)

                        Fixed priorities: the task that repeats most often gets the highest priority. How to test it and how to draw its Gantt chart by hand.

                        PYQ: A-Q4 (10 M)PYQ: B-Q5 (15 M)PYQ: D-Q5a (5 M)

                        Your path through this unit

                          1Learn it, step by step

                          Lesson 1

                          Where RMS fits

                          Write this in the exam
                          • Scheduling = how processes are assigned to run on the available CPUs. Real-time scheduling decides which ready process gets the CPU so that deadlines and response times are met.
                          • Real-time systems use pre-emptive multitasking with priorities; the RTOS always runs the highest-priority ready task.
                          • Fixed priority: assigned at design time, constant for the task's lifetime (e.g. RMS). Dynamic priority: assigned at run time from parameters such as the upcoming deadline (e.g. EDF). Mixed: both static and dynamic components.

                          Remember: RMS = fixed priority by period · EDF = dynamic priority by deadline.

                          Check yourself: is RMS pre-emptive?

                          Yes. A running task is pre-empted as soon as a task with a shorter period becomes ready.

                          Lesson 2

                          RMS: shortest period = highest priority

                          In plain words

                          "Rate" = how often a task comes back (1/T). The task with the highest rate (smallest period) gets the highest priority, and that priority never changes. It is simple, predictable and easy to certify, which is why it is used in deterministic embedded systems.

                          Write this in the exam

                          Concept: the task with the shortest period executes with the highest priority. RMS is fixed-priority and pre-emptive: a task is pre-empted if another task with a shorter period is ready.                           MODULE 5 · UNIT 8

                          Earliest Deadline First (EDF)

                          Dynamic priorities: whoever's deadline is nearest runs first. It is the optimal uniprocessor algorithm.

                          PYQ: A-Q5 (10 M)PYQ: C-Q5 (10 M)PYQ: D-Q5 (10 M)

                          Your path through this unit

                            1Learn it, step by step

                            Lesson 1

                            EDF: nearest deadline runs first

                            In plain words

                            Like a student doing homework: you always work on the assignment due soonest. Priorities change all the time, because the same task can be most urgent now and least urgent later.

                            Write this in the exam
                            • Concept: the task closest to the end of its period (earliest absolute deadline) gets the highest priority.
                            • Dynamic-priority, pre-emptive: a task is pre-empted if another task with a nearer deadline becomes ready.
                            • Optimal: if any algorithm can schedule the task set, EDF can.
                            • Tie: if two tasks have the same deadline, choose either (at random). In most cases the currently executing task continues, to avoid context-switch overhead.

                            Remember: absolute deadline = release time + D; the smallest one runs.

                            Check yourself: T1 released at 4 with D = 4; T2 released at 0 with D = 10. At t = 4, who runs?

                            T1's absolute deadline is 8 and T2's is 10, so T1 runs.

                            Lesson 3

                            Drawing an EDF Gantt chart, including arrival times

                            Recipe
                            1. List job releases: task i releases at Aᵢ, Aᵢ + T, Aᵢ + 2T, … (Aᵢ = arrival/offset, default 0).
                            2. Each job's absolute deadline = release + D.
                            3. At each time unit, among released unfinished jobs, run the smallest absolute deadline. On a tie, keep the job already running.
                            4. Recheck whenever a new job arrives (it may pre-empt).
                            5. Continue for one hyperperiod after the last first arrival, and mark deadlines and misses.
                            Tip: Write a small table above the chart: time · ready jobs with their deadlines · chosen. It shows the examiner why each choice was made.

                            Remember: release + D = deadline; smallest deadline runs; recheck at every arrival.

                            Check yourself: at t = 5, the ready jobs are T1 (deadline 10) and T3 (deadline 7, currently running). Who runs?
